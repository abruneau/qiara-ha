## What Was Painful

### SDK Integration Complexity (identified by Antonin as biggest pain point)

The root cause was that nobody fully understood the Qiara authentication protocol before dev started. The architecture doc says "adapt the SDK" but doesn't describe *how* the SDK authenticates.

**Cascade of issues:**
- No auth flow implemented (challenge/response HMAC-SHA1 was unknown to dev agent)
- arm/disarm fell back to Bearer tokens (wrong protocol)
- SDK Node fields (`type_name`, integer `id`) not mapped to Pydantic models — would have silently failed in production with real API data
- Config flow missing entirely — not scoped in Epic 2 at all

**Resolution:** The working example shared during code review was the first time the actual auth protocol was clearly documented. This unblocked the correct implementation.

### Known Technical Debt Carried Forward

- `QiaraSensorData.state` defaults to `"unknown"` — the `/nodes` endpoint returns device list only, not live state
- **Resolution path identified in this retrospective:** `/endpoints_read` returns live node states and can be correlated with node IDs. Accepted as known gap for Epic 2.

## Patterns to Keep

- **Adversarial code review** — caught critical issues. Non-negotiable step going forward.
- **`_map_node()` explicit mapping layer** — translate SDK response fields → Pydantic models explicitly. Epic 3 needs the same for alarm state.

## Patterns to Kill

- **Starting implementation without a working API example** — story 2-2 was written without dev knowing what `/challenge`, `/session`, or `/nodes` actually returned. Fix: include working example or API call reference in Dev Notes for every new endpoint.

---

## Critical Discovery — API State Endpoint

During this retrospective, Antonin identified the missing endpoint:

- **`/endpoints_read`** — returns live state for nodes; correlates with node IDs from `/nodes`

This resolves two gaps:
1. **Epic 2 debt:** `QiaraSensorData.state = "unknown"` — coordinator needs to call `/endpoints_read` and merge state
2. **Epic 3 blocker:** Alarm state readback — how to reflect current armed/disarmed status in HA

This information must be documented in project knowledge and referenced in Epic 3 story creation.
